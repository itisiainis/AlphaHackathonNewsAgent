# BO-1. Панель управления банка и обучение сервиса на опыте

**Зачем.** Банк должен видеть, хорошо ли работает сервис и доволен ли клиент, и управлять им без программиста.
Сервис должен становиться лучше с каждой новостью, разбором и оценкой, но дообучать модели по условиям кейса нельзя.

## В объёме
- `backend/admin.py`: API `/api/admin/*` по токену `ADMIN_TOKEN` — обзор и «требует внимания», запросы менеджеру
  со статусом, оценки, разборы (скрыть / вернуть / пересчитать / шаги), запуски ИИ, настройки на лету, сбор новостей,
  сводка обучения, журнал действий.
- `agent/learning.py`: память разборов, веса тем по оценкам, рутина в потоке, уроки проверки; выключатель.
- Интерфейс `#admin` (вместо «Качество сервиса», старая ссылка `#quality` ведёт туда же).
- Документация: `docs/product.md`, `README.md`, `.env.example`, `render.yaml`.

## Вне объёма
- Вход сотрудников через единый вход банка и роли внутри панели (в рабочей версии — каталог сотрудников банка).
- Дообучение моделей; отправка запросов менеджеру в CRM.

## Критерии приёмки → тесты
| Критерий | Тест |
|---|---|
| Без токена и с неверным токеном — 401 на каждом маршруте панели | `test_admin_requires_token`, `test_every_admin_route_requires_token` |
| Без `ADMIN_TOKEN` панель закрыта (503) | `test_panel_closed_without_admin_token` |
| 10 неверных попыток в минуту — 429; токен не попадает в журнал | `test_failed_attempts_are_limited_and_token_not_logged` |
| Скрытый разбор пропадает из ленты клиента и возвращается | `test_hidden_card_disappears_for_client` |
| Скрытый разбор не выдаётся из памяти | `test_memory_reuses_same_story_for_same_company_only` |
| Настройки проверяются по пределам (лимит ≤ 100 ₽, модели из списка кейса), применяются, сохраняются, пишутся в журнал | `test_settings_validated_applied_persisted_and_audited` |
| Необработанный запрос менеджеру виден в «требует внимания» и закрывается | `test_overview_flags_requests_and_offline_model` |
| Рутина распознаётся только после 3 разных дней; выключатель отключает | `test_routine_needs_several_days` |
| Веса тем сдвигаются оценками со сглаживанием | `test_feedback_moves_topic_weights_smoothly` |
| Память и прецеденты — только своей компании | `test_memory_reuses_same_story_for_same_company_only`, `test_precedents_are_isolated_per_company` |
| Урок активен после 2 повторов | `test_lessons_activate_after_repeats` |
| Сквозной сценарий в браузере, 375 и 1280 px, без ошибок | ручная проверка Playwright (отчёт в PR) |

## Риски
- Токен один на всех сотрудников: имя в журнале — со слов сотрудника. Для рабочей версии — вход через каталог банка.
- Настройки в памяти процесса: при нескольких копиях сервиса применяются при перезапуске каждой копии.
- Память разборов может выдать разбор похожего, но другого события: порог сходства 60% и срок 7 дней;
  сотрудник может скрыть такой разбор, и он перестанет выдаваться.
