# Обучение сервиса на опыте: проверка на данных

Механизмы обучения (`agent/learning.py`) сначала были написаны по соображениям здравого смысла и проверены
только модульными тестами: тесты подтверждали, что код делает то, что задумано, но не то, что задуманное
улучшает выдачу. Ниже — замер каждого механизма на реальных данных, найденные ошибки, исправления и
ограничения. Все цифры воспроизводятся без модели и без сети:

```bash
python -m scripts.eval_learning all        # ≈ 2 мин
```

## 1. Память разборов: «тот же сюжет»

**Вопрос.** Можно ли отдать готовый разбор новости, если «такую же» уже разбирали для этой компании?
Ошибка здесь дорогая: клиент получает разбор другого события.

**Было.** Сюжет считался тем же при сходстве основ слов заголовков ≥ 0,6 (коэффициент Жаккара), числа и
даты при сравнении отбрасывались.

**Результат.**

| Правило | Выборка | Совпадений | Ошибочных |
|---|---|---|---|
| только сходство ≥ 0,6 | разработка | 98 | 56 (57%) |
| только сходство ≥ 0,6 | **проверка** | **92** | **54 (59%)** |
| сходство + запреты | разработка | 38 | 2 (5%) |
| сходство + запреты | **проверка** | **28** | **0** |

Больше половины совпадений прежнего правила — разные события. Причины (выборка проверки): расходятся
числа или даты — 41 («ЦБ установил официальные курсы валют на 20 октября» и «…на 21 октября»;
«индекс Мосбиржи +0,34%» и «−0,07%»), тот же источник в другой день — 10, разные названия — 3
(«Аэропорт Внуково…» и «Аэропорт Шереметьево…»). Есть и противоположности: «Трамп поздравил…» /
«Трамп не поздравил…» (сходство 0,71), «Brent подорожала» / «подешевела».

**Решение** (`agent/stories.py`). Поверх сходства — запреты, каждый из найденной ошибки: расходятся числа,
даты, месяцы, дни недели; тот же источник в другой день; разные имена собственные с обеих сторон; отрицание
с одной стороны; противоположное направление. Порог 0,6 зафиксирован до проверки. На независимой выборке —
0 ошибок из 28 совпадений: с 95% уверенностью точность не ниже 89% («правило трёх»: 1 − 3/28).
Цена — полнота: правило находит 28 из 49 верных пар выборки (пересказы одного события другими словами
сходство не набирают). Для памяти это приемлемо: пропуск стоит одного запуска модели, ложное совпадение —
неверного ответа.

**Изменения после проверки** (честно: проверены на тех же выборках, новой независимой не было):
синонимы названий («ЦБ» = «Банк России», «ЕС» = «Евросоюз»), подписи изданий («— ТАСС») не считаются
участниками, слово с заглавной в начале второго предложения не считается именем, дни недели исключены из
сравнения слов (они — часть даты). Итог на выборке проверки после изменений — 0 ошибок из 28.

## 2. Склейка дублей при сборе новостей

Сборщик (`agent/ingest/collect.py`) склеивал похожие заголовки в одно событие тем же сходством —
и с той же ошибкой: новость нового дня пропадала внутри вчерашней («Топ-5 новостей дня — 30 сентября»
поглощала выпуски до 19 октября, если собирать за раз). В штатном режиме (пачки по 48 часов, 21 день)
прежний сборщик сделал 99 склеек, новый (те же запреты) — 65, общих 63. Из 36 склеек, которых больше нет,
28 были ошибочными (выпуски шаблона в разные дни, разные аэропорты, «рост» / «снижение» индекса,
доклады ОПЕК / МЭА), 8 — настоящие дубли, которые теперь покажутся двумя событиями. Худший случай сменился
с «новость пропала» на «новость показана дважды».

## 3. Рутина в потоке

**Было.** Сюжет — рутина, если точная подпись заголовка (основы слов без чисел) встречалась в 3 разных
днях. **Замер:** за 21 день — 1 сюжет (цена Brent). Заголовки шаблонов отличаются хотя бы словом,
точное совпадение почти не бывает. При ослаблении до сходства ≥ 0,4 в «рутину» попадает важный
продолжающийся сюжет (удары по НПЗ — 6 заголовков разных изданий) — ошибка, вредная для топливных компаний.

**Решение** (`agent/stories.py`, `template_days`). Шаблон — заголовки **одного источника** со сходством
≥ 0,6 в 3+ разных днях, у которых **меняются детали** (дата, число, день недели), или короткий заголовок
без чисел («Важное к началу основной сессии»). Повтор длинного заголовка с теми же цифрами — освещение
события, а не рутина: так в рутину перестали попадать опросы аналитиков перед заседанием ЦБ.

**Результат.** Помечено 184 поста из 5 455 (3,4%), 47 групп: «Что произошло за день: …», «Официальные курсы
ЦБ РФ с …», «На 10:10 мск у индекса Мосбиржи …», календари, «Топ-5 новостей дня — …». Ручная проверка
групп: одна ошибка — повтор одного поста («Strive Вивека Рамасвами…»), его понижение безвредно. Правило
подбиралось на этих же данных, поэтому оценка оптимистична. **Вклад механизма мал:** шаблонами оказались 19 событий
из 1 779, но они проходят отбор у многих компаний — 473 из 15 674 пар «событие × компания» (3,0%). Это уборка
шума, а не источник качества.

## 4. Оценки клиентов «Полезно / Не про нас»

Реальных оценок пока нет, поэтому — **симуляция на реальных лентах**: 109 компаний, у которых отбор
оставил ≥ 8 событий за 21 день (ленты — настоящие, `agent.matching.rank`); клиенты — синтетические.
Истинная полезность события для компании = балл отбора + Σ по темам (вес роли + индивидуальное отклонение
компании ~ N(0; 0,5)) / 2. Клиент видит 5 верхних событий и оценивает одно; 15% оценок ошибочны. Оценивают
15 компаний по 30 раз. Качество — NDCG@3 (на главной 3 события). 20 прогонов, 95% доверительные интервалы.

Неизвестны две вещи, поэтому все варианты проверены на сетке:
- **как клиенты оценивают** — относительно (лучше ли других показанных) или абсолютно (полезна ли вообще);
- **насколько клиенты отличаются от своей роли** — случайно или противоположно (оценивают только компании
  без кредита, которым ставка и долг не важны, а компаниям с кредитом — важны);
- дополнительно — **формула ленты откалибрована неверно** (темы на деле важнее вчетверо).

**Сравнивались:** без обучения; сумма голосов по темам (прежняя формула); «подъём» — насколько тема
одобряется чаще, чем клиент одобряет в среднем; подъём со сдвигом только при значимом отличии
(≥ 5 оценок темы, z ≥ 2).

**Результат: разница NDCG@3 с «без обучения» у оценивавших клиентов, пункты × 100**

| Калибровка | Клиенты | Оценка | Сумма голосов | Подъём | Подъём, значимый |
|---|---|---|---|---|---|
| верная | случайные | относительная | −2,7 ± 1,3 | −0,9 ± 0,2 | −0,6 ± 0,3 |
| верная | случайные | абсолютная | −3,1 ± 0,6 | −0,5 ± 0,3 | −0,1 ± 0,1 |
| верная | противоположные | относительная | −0,6 ± 2,7 | **+3,2 ± 1,3** | +1,8 ± 0,9 |
| верная | противоположные | абсолютная | −4,5 ± 1,1 | +1,5 ± 1,2 | +0,1 ± 0,7 |
| неверная | случайные | относительная | −2,2 ± 1,7 | +2,2 ± 0,9 | +2,0 ± 0,8 |
| неверная | случайные | абсолютная | **+4,8 ± 1,2** | +0,2 ± 0,6 | +0,7 ± 0,6 |
| неверная | противоположные | относительная | **−7,3 ± 2,2** | +0,6 ± 1,1 | +1,3 ± 0,9 |
| неверная | противоположные | абсолютная | +4,5 ± 1,8 | +0,1 ± 0,7 | +0,4 ± 0,5 |
| | | **худший случай** | **−7,3** | −0,9 | **−0,6** |

**Выводы.**
1. Прежняя формула опасна: в зависимости от неизвестного поведения клиентов она то добавляет до 5 пунктов,
   то отнимает до 7. Её выигрыш при неверной калибровке объясняется тем, что почти все оценки «полезно»
   и она поднимает все темы разом — то есть чинит масштаб формулы, а не учит предпочтения.
2. Когда формула ленты и веса ролей верны, лента уже почти идеальна (NDCG 0,996) и любое обучение по
   оценкам добавляет в основном шум.
3. Выбран подъём со сдвигом только при значимом отличии — по принципу минимального худшего случая:
   ухудшение не больше 0,6 пункта при сохранении примерно двух третей выигрыша там, где клиент
   действительно отличается от своей роли.
4. **Это подстройка, а не главный источник качества:** выигрыш не больше 2 пунктов NDCG@3. Качество ленты
   определяют отбор по профилю и веса ролей.

Формула симуляции совпадает с кодом `agent/learning.py` (проверено на 400 случайных оценках, расхождение
0,001 — округление). Механизм ограничений обмана не учитывает: один клиент с массовыми оценками сдвигает
только свою ленту и — через общий опыт роли — темы, где отличие значимо по всем оценкам роли.

## 5. Уроки проверки

**Вопрос.** Верно ли повторяющиеся замечания проверки превращаются в правила для агента?

**Замер** на 20 реальных замечаниях (разметка категорий вручную по полному тексту, привязана к хешу
текста): прежние правила — точность 0,75, полнота 0,35; новые — 0,93 и 0,96.

Что было не так: самая частая реальная ошибка — **факт привязан не к тому источнику** (в 11 замечаниях из 20:
«ссылка S8→S1», «привязан к src=1, но…») — уроком не покрывалась вовсе; урок про «ДКП» срабатывал на
процитированный текст черновика, а не на слова проверки (2 срабатывания из 2 — ложные); формат ответа
путался с «правка не прошла проверку». Исправлено: урок о привязке источника, цитаты из черновика
вырезаются до сопоставления, ошибки схемы ответа — отдельной категорией.

**Ограничение:** правила писались по тем же 20 замечаниям, оценка оптимистична; других реальных замечаний
пока нет. **Не измерено главное** — уменьшают ли уроки число правок и время разбора. Для этого нужен
A/B-прогон на реальной модели: 6 событий × 2 варианта (с уроками / без) × 3 повтора = 36 запусков,
≈ 0,3–0,6 ₽ за запуск, всего ≈ 11–22 ₽ общего ключа. Не запускался без согласия команды из-за бюджета.

## Ограничения

- Разметка пар и замечаний — один человек; согласованность разметчиков не измерялась.
- Выборка проверки для памяти — 116 пар; граница точности (≥ 89%) широкая.
- Рутина и уроки проверены только на данных, по которым подбирались правила.
- Оценки клиентов — симуляция: поведение реальных клиентов неизвестно. Когда наберутся реальные оценки,
  доля «полезно» в панели управления покажет, какая модель поведения ближе; формулу стоит перепроверить
  повтором накопленных оценок (`python -m scripts.eval_learning feedback` на реальных данных).
- История за 3 недели; сезонные и редкие шаблоны (ежемесячные публикации) в ней почти не видны.
