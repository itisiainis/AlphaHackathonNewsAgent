# Новостная аналитика для Альфа-Бизнеса

Сервис внутри интернет-банка Альфа-Бизнес для руководителей крупных компаний (выручка от 15 млрд ₽).
Он берёт профиль компании, отбирает из потока новостей события, значимые именно для неё, и объясняет их
влияние с опорой на аналитику Альфа-Банка: что произошло, почему это важно компании, риски и возможности,
что можно сделать, как оценивает банк и на чём основан вывод. У каждого утверждения видно происхождение:
**факт** из источника, **позиция банка** или **вывод ИИ**.

Решение кейса «Новостная аналитика для принятия бизнес-решений» (Альфа-Банк × Changellenge).
Условия и критерии с привязкой к решению — [`docs/criteria.md`](docs/criteria.md).

## Быстрый старт

Нужен Docker с Compose.

```bash
git clone <адрес репозитория> && cd AlphaHackathonNewsAgent
cp .env.example .env        # впишите LLM_BASE_URL и LLM_API_KEY; без них сервис тоже запустится
docker compose up --build
```

Откройте **http://localhost:8000**. Документация API — http://localhost:8000/docs.
Ключ модели не обязателен: без него сервис работает в режиме краткого разбора (см. таблицу ниже).

Windows (PowerShell):

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Развёртывание в облаке (Render, Railway) — [`docs/deploy.md`](docs/deploy.md).

Признак успешного запуска: в логе `Uvicorn running on http://0.0.0.0:8000`, на странице — главная интернет-банка
с виджетом «Важное для вашего бизнеса».

## Сценарий проверки

Кто пользуется сервисом, какие задачи бизнеса он решает и сценарии демо по ролям — [`docs/scenarios.md`](docs/scenarios.md).

1. **Главная** (`#home`): виджет «Важное для вашего бизнеса» — 3 события на разные темы с главным выводом под роль (точка входа, критерий 08). Ниже — «Чувствительность бизнеса»: факторы, через которые события влияют на компанию (процентный риск, концентрация выручки, зависимость от крупных плательщиков, валютный риск, отраслевые налоги), и свежее событие по каждому; затем сводка из данных банка: выручка, продукты, ВЭД, откуда приходят деньги и кому платит компания.
2. Нажмите на событие — откроется **лента** с раскрытой карточкой: событие, вывод под роль, 2–3 обоснования с метками факт / банк / ИИ / вывод по правилам, ниже — полный разбор.
3. Переключите **роль** в шапке (финансовый директор → генеральный директор): тот же факт, другой вывод и порядок ленты.
4. В раскрытой карточке: **«Как получен вывод»** — шаги агента и время (критерии 10–11); **«Задать вопрос»** — ответ с графиком (критерий 09); ссылки на источники ведут к первоисточнику; **«Обсудить с менеджером»** — запрос с комментарием, он сохраняется и учитывается в метриках.
5. Переключите **компанию** на девелопера и опт металлов: другая лента; у металлов — плашка качества данных и пометка устаревшей аналитики банка (2021 год) (ограничение 06).
6. Выберите любую другую компанию (список сгруппирован по отраслям): лента сразу содержит краткие разборы трёх самых значимых для неё событий — без вызова модели; ниже — **«Ещё новости по вашему профилю»** с объяснением «Почему вам» (критерий 01). С ключом — кнопка «Полный разбор ИИ».
7. **«Получить разбор»** у новости из списка или поле **«Ссылка на новость — оценим влияние на компанию»** в начале ленты — вставьте ссылку на любую новость (сайт, пост Telegram, PDF) или её текст (критерий 04). С ключом агент выполнит план, вызовы инструментов, расчёт, черновик и самопроверку; без ключа — краткий разбор правилами с пометкой. Карточка появится в ленте.
   Пример для расчёта: «Банк России снизил ключевую ставку с 16% до 14% годовых» → в карточке блок **«Сколько это в деньгах»**: −20 млн ₽ в год на каждый 1 млрд ₽ плавающего долга; введите свою сумму — пересчёт на месте.
8. **«Качество сервиса»** (внизу меню, для сотрудников банка) — обратная связь, запросы менеджеру из карточек, доля карточек, прошедших проверку, расход модели, точность отбора на размеченном наборе (критерий 12).

## Архитектура

```
Источники новостей (RSS, t.me/s)       Аналитика банка (9 PDF-сканов)       Данные о компаниях (3 CSV)
        │                                        │                                   │
 agent/ingest/collect.py                agent/ingest/bank_docs.py             data/company_profiles.json
 сбор, склейка дублей, темы,            OCR (Tesseract), дата, название,      (скрипт build_profiles.py —
 отрасли, отсев рекламы; Gemma          фрагменты по страницам                  у команды, см. docs/data.md)
        │                                        │                                   │
        ▼                                        ▼                                   ▼
 data/news/events.json ──► agent/matching.py ◄── agent/profiles.py (признаки, качество данных)
                          отбор правилами, без LLM: продукты банка, ВЭД, отрасли компании и контрагентов
                                   │ пары «событие × компания» выше порога
                                   ▼
                          agent/loop.py — свой агентный цикл (без фреймворков)
                          план → инструменты (agent/tools.py, только чтение, журнал вызовов)
                          → обязательный поиск позиции банка → расчёт эффекта кодом (agent/impact.py)
                          → черновик (GLM) → проверка кодом (agent/contract) + моделью (DeepSeek)
                          → повторный поиск и правка при замечаниях
                          модель недоступна → agent/offline.py: краткий разбор — выводы по правилам (agent/channels.py), без ИИ
                                   │ карточка по JSON Schema
                                   ▼
                          backend/app.py (FastAPI) + SQLite-кеш ──► frontend/template.html
```

Ключевые решения:

| Решение | Почему |
|---|---|
| Отбор событий — правилами по профилю, без LLM | Объяснимо (видно, на какой признак сработало), бесплатно, укладывается в 500 ₽/день: модель запускается только на отобранные пары |
| Поиск по аналитике — BM25 | В списке разрешённых моделей нет embedding-моделей; BM25 локален и объясним |
| OCR Tesseract для аналитики банка | PDF кейса — сканы без текстового слоя; локальный OCR не тратит бюджет модели. Qwen3-VL зарезервирован для графиков |
| Метки источников S1, S2… вместо ссылок от модели | Модель не может выдумать ссылку; код превращает метки в индексы источников |
| Проверка карточки кодом | Каждое fact/bank-утверждение должно иметь источник; числа сверяются с текстом источника; аналитика старше 12 месяцев помечается и не идёт в вывод |
| Проверяющая модель ≠ пишущая | Независимая самопроверка (GLM пишет, DeepSeek проверяет) |
| Кеш ответов модели и карточек | Повторный показ не тратит бюджет |
| Эффект в рублях считает код, а не модель | Модель плохо считает; формула, входные данные с происхождением и допущения видны пользователю. Сумм долга и импорта в данных нет — эффект на 1 млрд ₽ базы с полем для своей суммы |
| Скрытые рассуждения модели выключены там, где не нужны | Замер: проверяющая модель тратила >6000 токенов на рассуждения (~1 ₽ за вызов); без них — тот же ответ в 4 раза дешевле. Черновик рассуждает |
| Полный текст статьи по ссылке | RSS часто даёт только анонс; сервер читает статью (HTML, Telegram, PDF) с защитой от SSRF. Если доступен лишь анонс — так и написано в основании вывода |
| Краткий разбор без модели | Сервис полезен и при запуске без ключа (ключ команды публиковать нельзя) и при исчерпании бюджета |

Формат карточки — [`agent/contract/card.schema.json`](agent/contract/card.schema.json). Он же — формат обмена
между компонентами (рекомендация слайда 13): факты, источники, признаки клиента, оценка релевантности, риски
и возможности, разделение на подтверждённую информацию, позицию банка и выводы модели.

## Обучение на опыте и панель управления банка

Чем больше новостей, разборов и оценок, тем точнее отбор, лучше выводы и быстрее ответ. Модели дообучать нельзя
(только разрешённые, через API), поэтому учится всё вокруг них — `agent/learning.py`:
память разборов, веса тем по оценкам «Полезно / Не про нас», шаблоны в потоке, уроки проверки. Каждое правило
выбрано по замеру на реальных данных (22 дня новостей, 289 размеченных пар заголовков, 20 замечаний проверки,
симуляция на лентах 109 компаний) — [`docs/experiments/learning.md`](docs/experiments/learning.md),
воспроизводится командой `python -m scripts.eval_learning all`. Замер нашёл и исправил ошибку: прежнее сравнение
сюжетов в 54 случаях из 92 принимало за повтор разные события (вчерашний «курс ЦБ на 20 октября» — за новость
про 21-е). Разборы одного клиента другому не показываются.

Сотрудник банка видит и меняет всё это в панели управления (`/#admin`, токен `ADMIN_TOKEN`): требующее внимания,
опыт клиентов, запросы менеджеру, разборы (скрыть, пересчитать, посмотреть шаги), динамика обучения, настройки
(лимит, порог отбора, источники, модели по задачам) и журнал изменений.

## Безопасность AI-компонента (ограничение 05)

- **Белый список моделей** в `agent/llm.py`: вызов модели не из списка кейса падает до сетевого запроса.
- **Инструменты агента только читают** данные; набор фиксирован (`agent/tools.py`), неизвестный инструмент отклоняется, лишние аргументы отбрасываются и пишутся в журнал.
- **Чтение ссылок пользователя** — только публичные адреса: внутренние сети, loopback, метаданные облака и не-HTTP схемы запрещены, редиректы перепроверяются, размер ответа ограничен (`agent/ingest/article.py`).
- **Изоляция данных клиента**: сессия инструментов привязана к одной компании — профиль другой компании агент получить не может (тест `test_tool_session_cannot_read_other_company`).
- **Журнал вызовов инструментов** (имя, аргументы, время, размер результата) — в трассе карточки и в ответе API.
- **Дневной лимит расхода** и учёт стоимости каждого вызова; **ограничение частоты** платных запросов (`RATE_LIMIT_PER_MIN`).
- **Вывод модели — недоверенные данные**: проверка по JSON Schema и правилам происхождения; в интерфейсе весь текст экранируется.
- Ключи — только в `.env` (в git не попадает); заголовки безопасности (CSP, nosniff, запрет встраивания во фреймы).
- **Панель управления банка** (`/api/admin/*`) — только по токену `ADMIN_TOKEN` в заголовке (без него закрыта); одна проверка на все маршруты, сравнение за постоянное время, 10 неверных попыток в минуту с адреса — пауза; отказы пишутся в журнал сервера без токена. Токен — в заголовке, а не в cookie, поэтому межсайтовая подделка запроса (CSRF) не сработает. Настройки проверяются по пределам: лимит расхода не выше 100 ₽, модели — только из списка кейса. Каждое изменение — в журнале действий.
- В прототипе **нет аутентификации клиента**: вход в интернет-банк смоделирован переключателями. В рабочей версии — сессия интернет-банка, и компания берётся из неё, а не из запроса.

## Конфигурация

Все параметры — переменные окружения, полный список с комментариями — [`.env.example`](.env.example).

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | OpenAI-совместимый доступ к разрешённым моделям (общий ключ кейса) |
| `LLM_MODEL_*` | идентификаторы моделей у провайдера, если отличаются от названий кейса |
| `LLM_PRICE_*` | тарифы, ₽ за 1 млн токенов «вход,выход» — для учёта расхода |
| `LLM_DAILY_BUDGET_RUB` | дневной лимит сервиса (по умолчанию 50 ₽: ключ общий на команду, 500 ₽/день) |
| `RATE_LIMIT_PER_MIN` | платных запросов в минуту с одного адреса |
| `COLLECT_ON_START` | собирать свежие новости при запуске (в Docker — 1) |
| `APP_TODAY` | зафиксировать дату «сегодня» для воспроизводимой демонстрации |
| `ADMIN_TOKEN` | токен панели управления банка (`/#admin`); пусто — панель выключена |

Большую часть настроек сотрудник банка меняет и в панели управления — без перезапуска; сохранённые там значения важнее переменных окружения.

Источники новостей — [`data/sources.json`](data/sources.json): новый источник добавляется строкой, без изменения кода.

## Масштабирование и сопровождение (критерий 07)

- **Новые источники** — строка в `data/sources.json`. **Новые материалы банка** — PDF в `data/raw/bank/` и `python -m agent.ingest.bank_docs` (пересчитываются только новые файлы, по хешу).
- **Новые отрасли** — словари `agent/okved.py` (подписи классов ОКВЭД2, основы слов, связанные отрасли для торговли); модель Gemma уточняет разметку.
- **Новые клиенты** — профиль строится из тех же трёх таблиц банка; отбор и интерпретация не зависят от конкретной компании.
- **Сопровождение** — CI (линтер, тесты, сборка и запуск образа) на каждый PR; панель управления банка (`/#admin`): качество, опыт клиентов, модерация разборов, настройки, журнал; `/api/metrics`; кеш ответов модели позволяет воспроизвести разбор.

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.lock -r requirements-dev.txt
pytest -q tests                                   # 394 теста, без сети и ключей
python -m scripts.eval_learning all               # замеры обучения на опыте (docs/experiments/learning.md)
ruff check .
uvicorn backend.app:app --reload                  # http://localhost:8000
python -m agent.ingest.collect 48                 # собрать новости за 48 часов
python -m agent.ingest.bank_docs                  # OCR аналитики (нужны tesseract-ocr, tesseract-ocr-rus, poppler-utils)
python -m scripts.run_agent U_25835 --top 1 --save  # разбор агентом из консоли и сохранение в data/cards (нужен ключ)
# дымовые проверки живого сервера (в конце каждой волны работ; против боевого сервера — с --no-model):
python scripts/smoke_demo.py --base http://127.0.0.1:8000 --strict
NODE_PATH=<путь к node_modules с playwright> node scripts/smoke_ui.js http://127.0.0.1:8000 /tmp/smoke-ui
```

Статический прототип без бэкенда: `python frontend/build.py` → `frontend/prototype.html`.
