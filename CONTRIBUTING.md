# Правила проекта

Хакатон Альфа-Банка, кейс «Новостная аналитика». Делаем сервис внутри интернет-банка Альфа-Бизнес
для руководителей крупных компаний (выручка от 15 млрд ₽): он берёт профиль компании, отбирает
значимые для неё события и объясняет их влияние с опорой на аналитику банка. Простой пересказ новостей
жюри считает провалом.

Подробности — в `docs/`: `product.md` (UX, экраны, решения), `data.md` (выводы по данным),
`criteria.md` (условия и 12 критериев из презентации кейса), `plan.md` (план и статус). Перед изменениями в интерфейсе или формате данных прочитай их.

## Жёсткие ограничения кейса
- В рантайме — ТОЛЬКО разрешённые модели: Gemma 4, GLM-5.3-Flash, Qwen3.6, DeepSeek-V4.1-Flash,
  Qwen3-VL, Kimi-K2.6. Никаких других коммерческих API моделей в коде решения.
- Готовые агентные фреймворки не должны быть основным компонентом — агентный цикл пишем сами.
- Бюджет общего ключа — 500 ₽/день: кешировать ответы, предрасчитывать карточки, дешёвые задачи → Gemma.
- Должно работать на новых, ранее не показанных новостях — никаких захардкоженных сценариев.
- Сдача: GitHub-репо, Docker (запуск одной командой), README, lock-файлы, THIRD_PARTY_NOTICES.

## Формат данных = контракт
`frontend/mock_data.json` — общий формат: агент выдаёт такой JSON, бэк отдаёт, фронт рисует.
Поля НЕ переименовывать и не удалять без договорённости команды. Ключевое:
- карточка: `id, type (risk|opportunity|info), impact (high|medium|low), topics[], is_new, title (событие),
  takeaway{cfo, ceo, treasurer, accountant?} (главный вывод под роль — короткий слой; главбух необязателен), key_points[] (2–3 обоснования),
  why_short, matched[], sources[{name, kind (news|bank|stat), date, url}],
  blocks{what, why, risks, opportunities, actions, bank, basis} (раскрываемый полный разбор), trace[], chat[]`
- утверждение: `{t: текст, p: fact|bank|ai|rule, src?: индекс источника, strength?: high|medium|low}`
- каждое утверждение обязано иметь происхождение `p` — это требование жюри (факт / позиция банка / вывод ИИ /
  вывод по правилам — собран кодом без модели, `agent/channels.py`).

## Принципы UX (не нарушать)
1. Сначала вывод, потом детали: карточка в свёрнутом виде = главный вывод под роль + 2–3 чипа с главными числами +
   позиция банка (если есть) + событие и источник мелко; полный разбор раскрывается на месте по нажатию
   (аккордеон, одна открыта за раз). Новизна — синим, важность — красным.
2. Мало и по делу: на главной 3 события; лента разбита на группы «Требует решения / Следить / К сведению».
3. У каждого утверждения видно происхождение цветом (факт — без выделения, банк — красный, ИИ — фиолетовый, правила — бирюзовый;
   слово — в подсказке и легенде) и источник.
4а. Простой причинный язык: «событие → что меняется → что это значит для вас → сколько»; без кодов ОКВЭД и жаргона
   («контрагенты», «входящий поток», «ДКП»). Факты и цитаты банка — дословно.
4. Из инсайта — шаг к действию (кнопка менеджера / продукт банка), только если обоснован.
5. Честность: нет данных — так и пишем («отраслевой оценки банка нет», «покрытие данных 21%»).
   Аналитику банка старше 12 месяцев помечаем устаревшей и не используем в выводе.

## Структура
- `frontend/` — сайт: `template.html` (отдаётся бэкендом и берёт данные из API; `build.py` → статический `prototype.html` на моках).
- `backend/` — FastAPI + SQLite. `agent/` — сбор, отбор, агентный цикл, промпты, инструменты; контракт — `agent/contract/card.schema.json`.
- `data/` — профили, источники новостей, аналитика банка после OCR (`data/bank/docs.json`), роли и зоны ответственности (`data/roles.json` — единый конфиг ролей).
- Качество готовых разборов: `python -m scripts.eval_cards` — в выводе есть данные именно этой компании, позиция банка с датой, действие; вывод не копируется другой компании.
- Проверки перед PR: `pytest -q tests` и `ruff check .`. Запуск: `docker compose up --build`.
- Исходные CSV лежат локально в `data/raw/`, в git не коммитятся.

## Правила работы
- В `main` — только через Pull Request с ревью второго человека.
- `.env` не коммитить; шаблон — `.env.example`.
- Меняешь формат данных или экран — обнови `docs/product.md` в том же PR.
